- [x] MSRV declared and enforced: `rust-version = "1.88"`, determined empirically (1.88 checks clean, 1.87 fails in backstory-core with E0658 on let-chains) and guarded by a dedicated CI job so it cannot drift.
- [x] Supported platforms stated in README (macOS arm64/x86-64, Linux x86-64; Windows explicitly unsupported). SUPERSEDED 2026-07-26: native Windows x86-64 is now supported. The analysis engine and MCP server already compiled for Windows unchanged; only `install.rs` did not, in three places, all Unix file-permission calls. Port: a single cfg-split `set_mode` helper (no-op on Windows, mode set on the temp file strictly BEFORE the atomic rename so there is no readable window at the final path), a shared `home_dir()` preferring HOME then falling back to USERPROFILE so WSL and git-bash keep working identically, `EXE_SUFFIX` for the sibling binary lookup that `install` depends on, and `#[cfg(unix)]` on the four symlink security tests (creating a symlink needs elevated privileges on Windows; the protections still apply, only the tests cannot run). Two deliberate gaps, both in the README: the Stop hook is a /bin/sh script so it is not installed on Windows, and installed files are not permission-restricted there. A `windows` CI job runs the FULL suite plus an `install --apply` / `uninstall --apply` round trip in a throwaway HOME, which is the only real verification since the port was written on a Mac. Fifth release archive added, still .tar.gz because Windows 10+ ships tar and one format keeps the release path uniform.
- [x] Onboarding: bare `backstory` now analyzes the newest session for the cwd's project instead of printing usage. Selection note goes to stderr so `--json`/`--html` stay pipeable; provenance is the already-reserved `cli_latest`. Shared newest-transcript logic moved down into `backstory-core::locate` (with an ADR A9 symlink guard, so a planted `<uuid>.jsonl -> ~/.ssh/id_rsa` with a fresh mtime is skipped rather than selected) and `backstory-mcp::identify` now calls it instead of duplicating it.
- [x] Payload caps enforced BY CONSTRUCTION for all six tools, not just `evidence()`. Measured before the fix: `blind_spots` was 3166 tokens against a 1000 budget on an ORDINARY session (no adversarial input needed), and `struggle_areas(n=99)` hit 2827 against 1500. Root cause was finding `idxs` (a churn finding on a file edited 800 times carries 800 indices). Now every builder runs the same shrink loop, all caller-controlled strings are capped first, every list has a k=0 floor so shrinking terminates, and disclosure fields (`*_total`, `list_cap`, `n_max`, `findings_omitted`, `idxs_total`) say what was dropped. Findings retained round-robin over the scoring categories in `review::SEVERITY_ORDER` so truncation no longer biases toward whichever detector emitted first.
- [x] `truncated` no longer fires merely because more than 3 files ranked (that is `top_struggles`' designed shape, and `top_struggles_total` discloses the real count). Rate on real sessions dropped from 20/40 to 8/40, so the flag carries signal again.
- [x] HTML "… N more" in blind spots now uses the pre-cap `totals` rather than the capped array length, which would have undercounted exactly the noisy sessions the note exists for.
